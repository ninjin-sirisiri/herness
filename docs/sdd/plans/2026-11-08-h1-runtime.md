# H1 Runtime and Audit Implementation Plan

**Goal:** macOS上で、独立したagentの実行・停止・再開、許可、変更理由の記録、認証と安全な復旧をherness所有の境界で提供する。

**Architecture:** TauriのRust hostが実行と保存を所有し、`pi-embedded`・`pi-ai`は交換可能なengine adapter内に閉じ込める。公開契約とtool gatewayを`herness-core`、transactionalなcheckpoint・auditを`herness-store`に置き、資格情報はmacOS Keychainへ分離する。WebViewは最小限の接続確認用画面とし、H2〜H5の実装は含めない。

**Tech Stack:** Rust / Cargo workspace、Tauri 2.12.5、pi-rust v0.12.11（commit `4294dba7ac3646477912cc778536fdff0a912d6e`）、SQLite、macOS Keychain、静的HTML/CSS/JavaScript、SDD packのPython 3.11+ validator。

**Spec:** [docs/sdd/specs/2026-11-07-h1-runtime-design.md](../specs/2026-11-07-h1-runtime-design.md)

## Global Constraints

| 項目 | 初期値・制約 |
| --- | --- |
| 公開する契約の版 | 1。未知の版を黙って解釈しない |
| rationale / purpose | trim後に空でない、最大1,000 Unicode文字 |
| 履歴ページ | 既定100件、上限500件 |
| 通常終了の停止猶予 | 10秒。その後は人間に待機継続・強制終了を確認 |
| 初期許可モード | 設定権限モード。自動モードは利用可能な評価器が必要 |
| 自動のgoal継続・判定閾値・費用上限 | H1では定めない。H2が定義する |

範囲外・非保証（specのNon-goals、およびNode runtimeの除外）:

- 完了条件までの再実行、判定モデルの実装、HTML同期・再構成、SDD Taskの進行、完成版UI・配布。これらはH2〜H5が所有する。
- Node runtimeは初期構成に含めない。
- 未信頼コードをOSで強制隔離する保証。信頼するプロジェクトが対象であり、許可済みシェルはOS権限を持つ。
- 専用の削除・移動・undo機能、自動push・merge・公開、アプリ終了後の常駐agentサービス。

実行・保存・後続phaseへの制約:

- SDK型やcheckpoint形式をUI・H2〜H5の契約に漏らさず、SDKは交換可能な内部依存とする。
- 変更前の永続記録に失敗したら書かない。実ファイル変更後の記録失敗では、無断で元へ戻さず結果不明として照合待ちにする。
- シェルのpurposeと出力は別に記録する。シェルが変更した各ファイルや、外部編集の理由を推測して付けない。H3へ渡すファイル変更通知も、確認できないactorを断定しない。
- 初期モードは設定権限モード。H2の評価器が利用できるまで自動モードは利用不可と表示し、勝手な別モデルへのfallbackはしない。判定用providerへの送信範囲・利用同意はH2で、実接続を有効にする前に確定する。
- 保存するAPIキーとOAuth tokenはmacOS Keychainに置き、DB・checkpoint・イベント・ログへ入れない。APIキー入力は信頼された設定画面からの一時的入力に限定し、保存後は再取得表示しない。通常ファイルの履歴はprivateなアプリ領域に保存し、任意の秘密値を完全に検出できるとは約束しない。
- 再起動時は保存状態を復元するだけで、勝手に実行・再送信しない。人間の再開操作で現在の資格情報・許可を確認する。過去の承認を復元しただけで再利用しない。
- H3・H4の連携定義が整う前に、親モデルへその責務を黙って戻す代替動作を入れない。
- H1の受入には、上記の自動検証、実Tauriと選定adapterの接続、実接続の確認結果が必要。spikeの73件成功は設計選択の証拠であり、これから作るherness実装のテスト結果として使い回さない。残る外部確認を免除する場合も、未確認の認証経路を利用可能・完成済みと主張しないよう人間と範囲を再合意する。

Taskは1から13へ直列に進める。各Taskは対応する自動テスト、実行コマンド・終了コード、対象commitまたは差分、未確認事項を報告する。外部接続は既定で無効とし、通常テストは一時project・一時DB・fake credential store・loopback mockを使う。実資格情報の探索、Keychainの既存項目の読取り、実ログイン・モデル送信はTask 13の別途許可より前に行わない。

文書の正本は[H1 spec](../specs/2026-11-07-h1-runtime-design.md)、用語は[CONTEXT.md](../../../CONTEXT.md)。[ロードマップ](../specs/2026-11-07-herness-roadmap.md)の「Specの分割」「依存関係と設計順序」「共通契約の所有者」に従い、H2の実評価器、H3のwatcher・HTML worker、H4のTask dispatch、H5の製品UI・配布を追加しない。`../sdd`は参照のみとし、既存host向けの設定・policyを本planで変更しない。

## Task 1: Rust workspaceとhost所有の契約を定義する

**Dependencies:** 承認済み[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のArchitecture、Shared contract全体、Numeric defaults。先行Taskなし。

**Paths / deliverable:** ルートCargo設定、`crates/herness-core/`、`tests/runtime/`のworkspace member、`docs/development/h1-testing.md`。`herness-runtime-tests`は後続のblack-box契約テストを持つlibrary crateとして登録する。store・engine・Tauriの空実装はこのTaskで作らない。

**Acceptance:**
1. project・agent・session・run・操作ID、run状態、version付きevent、構造化error、接続の非secret情報を定義する。`idle`とTask完了を区別し、未知versionと別project参照を拒否する。
2. engine・store・credential・permission evaluatorのportと、操作の最終引数・cwd・policy版を固定する値を定義する。Pi型・token・providerの生errorを公開型に含めない。checkpoint本体はversion付きopaqueデータとしてportを通し、解釈をadapter内に留める。
3. read・search・write・edit・bashの引数schemaと、非空・最大1,000 Unicode文字の検証を実装する。Unicode scalar数で境界をテストし、byte数やUTF-16長で代替しない。
4. 現在の互換Rust toolchainを確認して完全なversionを固定し、Cargo.lockを追跡する。ビルド成果物・一時DB・ローカル資格情報をGit対象から除外し、依存方針とテスト手順を記録する。

**Verification / evidence:** `cargo test -p herness-core`、`cargo test -p herness-runtime-tests`、`cargo fmt --all -- --check`。0・1,000・1,001文字、空白、非ASCII、未知version、ID取り違えの結果と、選んだtoolchainを報告する。

## Task 2: SQLiteのcheckpoint・audit・履歴を同一transactionで保存する

**Dependencies:** Task 1のportとID。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のArchitecture、Events and audit、Lifecycle and recovery、Store / integrationの受入条件。

**Paths / deliverable:** `crates/herness-store/`、`tests/runtime/tests/store.rs`。host所有のschema migration、project別sequence、checkpoint・操作意図・結果・許可版のtransaction、履歴取得を実装する。

**Acceptance:**
1. checkpointと対応するaudit/eventを原子的に保存し、commit済みのeventだけを購読側へ返す。副作用前の永続化失敗は実行不可として返せる。操作IDの重複を新規実行として扱わない。
2. privateなアプリデータ領域にDBを置くための設定境界を用意し、project内を既定保存先にしない。未知のDB・checkpoint versionを破棄せず読込みを拒否する。migration失敗で既存DBを壊さない。
3. 履歴は既定100・上限500、project指定必須、降順とする。cursorは最初の上限sequenceを固定し、ページ間の新規event・再接続で重複や欠落を作らない。live再配送は昇順で、操作の再実行に結び付けない。
4. 結果未記録の操作を抽出し、適用済み・未適用・照合不能を証拠とともに区別できる。復元だけで実行を起動するコードを持たせない。

**Verification / evidence:** `cargo test -p herness-store`、`cargo test -p herness-runtime-tests --test store`。commit前後・migration途中のfault injection、別接続での再読込み、ページ中の追加event、別project cursor拒否を報告する。

## Task 3: 許可モード・承認待ち・古い判断の失効を実装する

**Dependencies:** Tasks 1–2。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のPermission modes、Sessions and runs、Error handling。H2のモデル実装には依存しない。

**Paths / deliverable:** `crates/herness-core/src/permissions/`、`tools/gateway`の許可境界、`tests/runtime/tests/permissions.rs`。人間の設定変更とmodelのtool要求を区別するAPIを提供する。

**Acceptance:**
1. schema・保護境界・deny・askを優先する。設定モードはallow一致だけを実行可能とし、他は確認待ち。自動モードはdeny・ask以外をすべて評価器へ渡し、allowルールで評価を省略しない。
2. mock evaluatorでallow・deny・askと、不在・timeout・不正応答・判定不能を検証する。失敗ではtoolを呼ばない。実評価器不在の製品設定では自動モードを利用不可とする。
3. 判断を操作ID・最終引数・cwd・project・policy版に束縛する。引数・ルール・モード変更、run再開、二重承認・解決済み承認で古い許可を失効させる。実行直前に再確認する。
4. 子agentの権限は親から与えた範囲を超えない。shellの単純な接頭辞許可を安全保証にせず、構造化ルールの対象・一致方法を実装とfixtureで明示する。rationaleや読んだファイルで権限を変更しない。

**Verification / evidence:** `cargo test -p herness-runtime-tests --test permissions`。副作用counterが0の拒否ケース、承認とpolicy更新の競合、子agentの拡大拒否、評価器未接続の表示用capabilityを報告する。

## Task 4: 理由と差分を記録するnative file toolを実装する

**Dependencies:** Tasks 1–3のschema、store、許可境界。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のTools and rationale、Data flow、Error handling。

**Paths / deliverable:** `crates/herness-core/src/tools/`のpath・read・search・write・edit・gateway、`tests/runtime/tests/files.rs`。一時projectを使って、engineなしでもgatewayから実ファイル操作を検証可能にする。

**Acceptance:**
1. read・searchもrootと実パスの許可を通す。write・editはファイル単位のrationale、変更前の版、対象、意図した差分を確定し、checkpointと操作意図を保存してから書く。作成と編集の失敗条件を区別する。
2. 同一fileの書込みを直列化し、実行直前の版・実パスを確認する。symlink escape、未作成fileの親symlink、外部変更、同時編集を検知したら古い編集を適用しない。trusted-project境界以上のOS sandbox保証はしない。
3. 変更後の版と実際の結果を保存してから通知する。変更前保存失敗は無変更、変更後保存失敗は照合待ちとし、自動rollback・無条件再実行をしない。重複操作IDで二重適用しない。
4. SDD packのread権限をwriteに流用しない。H3が後で利用できる永続化済み変更通知を返すが、watcher・HTML著作・外部編集者の推測は実装しない。

**Verification / evidence:** `cargo test -p herness-runtime-tests --test files`。実際のbefore/after hash・差分・audit対応、理由なしで無変更、競合で上書きなし、書込み直後のfaultと別store接続からの照合を報告する。

## Task 5: purposeを持つbashと管理下process groupを実装する

**Dependencies:** Tasks 1–4のgatewayとaudit。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のTools and rationale、Permission modes、Lifecycle and recovery。

**Paths / deliverable:** `crates/herness-core/src/tools/`のbash・process管理、`tests/runtime/tests/shell.rs`。許可されたcwd・コマンド・purposeを固定し、hostが子プロセスを所有する。

**Acceptance:**
1. 空purpose・拒否・未承認・事前保存失敗ではプロセスを起動しない。stdout・stderr・終了code・signal・停止結果を操作と関連付け、purposeとは別に保存する。
2. 停止時は新規処理を止め、管理下process groupへ協調停止と必要な終了処理を行う。待機する子を回収し、停止を確認できなければ不確実として返す。意図的に切り離されたprocessの捕捉は保証しない。
3. シェルによるfile変更に個別のrationaleやactorを捏造しない。出力の流量で停止や保存を妨げない。出力を制限する場合は切詰めを明示し、失った出力を全量保存済みと表示しない。
4. 再起動時にコマンドを再送しない。shell結果不明はnative fileのhash一致だけで成功と決めず、人間による照合を可能にする。

**Verification / evidence:** `cargo test -p herness-runtime-tests --test shell`。fixtureの子・孫process、出力過多、停止中の保存失敗、事前拒否のspawn件数0、shell変更への理由未付与を報告する。

## Task 6: SDD pack参照・skill指紋・toolchain検出を実装する

**Dependencies:** Tasks 1–5。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のSkills and documents、Consuming paths。[ロードマップ](../specs/2026-11-07-herness-roadmap.md)のSDD pack所有境界。

**Paths / deliverable:** `crates/herness-core/src/skills/`、`tests/runtime/tests/skills.rs`、`docs/development/h1-testing.md`。`../sdd`全体を設定先として参照し、skillの原文とhost適用差分をrun contextへ渡す。

**Acceptance:**
1. pack root・skill path・原文digest・host差分を記録する。相対参照はpackの位置で解決し、個別SKILL.mdのコピーを正本にしない。run途中の変更を以前と同じ指紋として扱わない。
2. Git・Python 3.11+・利用者の検証ツールについて、明示した実行パスと検出結果を示す。Finderの最小PATH、Python旧版、不在、実行不能をテストし、不足時にcapability不足を返す。自動installや別validatorへの置換はしない。
3. HTML worker・SDD Task controllerのcapabilityは未実装として扱う。依存するskillの実行を利用可能と偽らず、親モデルdispatchへfallbackしない。H1のskill読込み自体とは区別する。
4. `../sdd`を編集せず、現在のTarget・Markdown先行編集・別HTML著作・共通validatorを維持する。

**Verification / evidence:** `cargo test -p herness-runtime-tests --test skills`。合成packの相対参照・変更検知に加え、`../sdd`の実skillをread-onlyで読んだ指紋・利用可否を報告する。実packの変更差分がないことを確認する。

## Task 7: 接続設定とKeychainのcredential境界を実装する

**Dependencies:** Tasks 1–6。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のModels and credentials、Tauri / security、Error handling。

**Paths / deliverable:** `crates/herness-core/src/connections/`、`src-tauri/src/credentials/`のKeychain adapter、`tests/runtime/tests/connections.rs`。このTaskではKeychain adapterをテスト可能な小さいRust libraryとして登録し、windowやIPCはまだ追加しない。

**Acceptance:**
1. OpenAI・Anthropic・OpenAI互換接続の非secret設定、資格情報参照、利用可能・要ログイン等の状態を提供する。保存APIはwrite-onlyとし、通常のUI取得・event・Debug・error・checkpointにsecretを出さない。
2. APIキーとOAuth token setをmacOS Keychainへ保存するadapterを実装し、通常テストはfakeを使う。Keychain拒否・lock・更新失敗で平文ファイルへfallbackしない。実KeychainアクセスはTask 13の検証用項目に限定する。
3. 利用者設定のHTTP(S) URLを検証し、remote HTTPには危険性の確認を要求する。別origin redirectへ認証headerを送らない。model・skillから接続先とcredentialを更新できず、無断provider fallbackをしない。
4. 接続ごとのcredential解決・refresh直列化と、失敗時に実行を止める境界を用意する。secretを含む合成error・URL・headerのredactionを検証する。

**Verification / evidence:** `cargo test -p herness-runtime-tests --test connections`、Keychain adapterのmockベースunit test。secret canaryがDB・checkpoint・event・ログへ出ないこと、cross-origin redirect先でheader未受信、別接続間の分離を報告する。

## Task 8: ChatGPTの公式OAuthフローと利用条件gateを実装する

**Dependencies:** Task 7のcredential portと設定境界。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のModels and credentials、Open items and resolution。実接続の許可はまだない。

**Paths / deliverable:** `crates/herness-engine-pi/src/auth/`、`tests/runtime/tests/oauth.rs`、`docs/research/2026-11-08-h1-chatgpt-auth.md`。engine crateをworkspaceへ登録し、認証ロジックはPiの旧OAuth helperと独立に検証する。

**Acceptance:**
1. 実装直前に[公式overview](https://developers.openai.com/siwc/token-sharing-open-source)、[sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)、[models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)を再確認し、確認日・適用条件・必要な差分を記録する。open-source / locally hosted向け条件への適合を確認できなければ利用不可とし、公開・license決定・有償提供・申請を勝手に行わず人間へ戻す。
2. host IDを初回前に永続化し、初回の`dynamic_agent_client`と発行済みclient IDを分ける。試行ごとにstate・nonce・PKCEを更新し、listenerを先に起動する。認められたloopback URIと同じURIでcodeを交換する。別clientの固定ID・秘密を流用しない。
3. state、署名・issuer・audience・expiry・nonce、返却client ID、検証済みaccount identity、付与scopeを検証する。account/client単位でtokenを分離し、新しいloginが検証されるまで既存の接続を置換しない。
4. 接続ごとにrefreshを直列化し、回転token setを一括更新する。取消し、callback再送、port競合、scope不足、更新失敗、sign-outとremote revoke未確認を安全に扱う。秘密とID token入りURLをログへ出さない。
5. mock以外へ接続しない。公式フローへの互換をPiの10件の旧mockテストから推定しない。公式条件に必要な機能をSDKが提供しない場合はhost側に狭いbridgeを実装し、SDK全体のforkへ広げない。

**Verification / evidence:** `cargo test -p herness-runtime-tests --test oauth`。loopback mock・合成署名鍵による正常系と上記拒否系、同時refresh、credential保存失敗の結果を報告する。実ログイン・実モデル接続は未確認と明記する。

## Task 9: pi-rust engineと全provider経路をhost toolへ接続する

**Dependencies:** Tasks 1–8のport、gateway、credential、skill context。[H1 spec](../specs/2026-11-07-h1-runtime-design.md)のApproach、Architecture、Engine adapter、Models and credentials、Events and audit。[spike結果](../../research/2026-11-07-pi-rust-spike.md)は設計根拠だけに使う。

**Paths / deliverable:** `crates/herness-engine-pi/`のadapter・SessionStore・StreamFn bridge、`tests/runtime/tests/engine.rs`、合成stream fixture。Pi依存を指定commitへ固定する。

**Acceptance:**
1. `pi-embedded`の独立context・作成・入力・停止・再開をcoreのengine portへ変換する。Pi組込みのfile・shell toolでgatewayを迂回させず、host所有の5 toolだけを登録する。
2. SDKのpending tool frameを、対応する操作意図・checkpointと同じstore transactionへ接続する。事前保存を待てないSDK経路で副作用を実行しない。tool ID重複、event再配送、未知snapshot、途中停止をテストする。
