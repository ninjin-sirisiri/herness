H3 HTML Sync and Reconstruction Implementation Plan

Goal: Target Markdownの変更から、全文情報と意味を保持したHTMLの著作・検証・H2評価・履歴付き反映までをhernessが自動制御する。

Architecture: SDD packがTarget・source unit・semantic-v1の静的契約を所有し、Rustのherness-html-syncが変更監視、世代、候補、反映と復旧を所有する。H1へ候補専用toolとhost反映境界、H2へpacket保持・実scope・承認済みowner起動・HTML評価を先行追加する。描画証拠はmacOSの非特権WebKitから取得し、状態・承認・予算・反映journalをSQLiteへ保存する。

Tech Stack: Rust 1.97.1 / Cargo workspace、Tauri 2.12.5、既存固定pi-rust、SQLite、Python 3.11+標準ライブラリ、静的HTML/CSS/SVG、macOS WKWebViewと既存lockに整合するobjc2 bindings。

Spec: docs/sdd/specs/2026-11-09-h3-html-sync-design.md

Global Constraints

以下はH3 specとH1/H2の承認済み追加契約から原文を引き継ぐ。

  • Target Markdownの内部編集・shell経由の編集・外部編集から、親モデルのdispatchなしでHTML用agentを起動する。
  • 全文情報と意味を保持し、本文の言い換え、順序変更、根拠のある図解・グラフ、補助的な要約を認める。逐語一致だけを完成条件にしない。
  • 最新の原文、候補、依存入力に対して検証・評価できた成果物だけを反映し、同期状態・競合・停止理由・証拠を後続phaseへ提供する。
  • Markdown正本、Targetの範囲、正確なbytesのdigest、静的な安全性、共通validatorを維持する。他ホストの標準動作を変えない。
  • Markdownの自動修正、機械的なMarkdown-to-HTML renderer、文書削除・移動の代行、Git操作、Task全体の完了判定、完成版preview UIは含めない。
  • 意味保持・認知負荷の軽減を数学的に証明すること、モデルの誤判定をなくすこと、外部processとの完全な同時実行分離は保証しない。
  • H4は、要求した文書版と依存入力が現在もsyncedであることを完了barrierとして照合する。H3の失敗はMarkdown編集や無関係なagentを止めないが、このbarrierを通さない。
  • 人間停止、人間待ち、停滞、上限、復旧照合待ちのlatchは、新しいファイル通知や原文版で解除しない。
  • 原文変更・世代交代でH2の消費予算をリセットしない。
  • 未検証候補で旧成果物を置換しない。現在の外部変更を巻き戻す自動rollbackは行わない。
  • 再起動はjob・latch・使用済み予算・反映journalを復元し、送信や著作を自動再開しない。
  • CIはnetworkもagentも使わず、静的安全性、digest、対応表の構造とcoverage、厳密保持対象、図の根拠構造、receiptと成果物・policyの結付きを検査する。意味や画像品質を独立再評価したとは表示しない。
  • H3はrepo内のreceiptだけを信頼してsyncedにせず、自身の保存済み評価・承認と照合するか新たに評価する。
  • 既存の閾値・送信同意・人間待ち・予算・許可優先順位は緩めない。

Task 1〜6はpack、Task 7〜25は主にhernessを変更する。Task 23では両方の結合を確認する。Taskを直列実行し、Taskごとのcommit・変更・証拠をrepo別に記録する。隔離を選ぶ場合もcontrollerが二つの作業先を最初に確定し、Taskごとにworktreeを作らない。実行時のSDD_PACK_ROOTは選択したpack checkoutの絶対パスとし、hernessをworktreeへ移しても../sddが正しいと仮定しない。別repoの書込み範囲が未許可なら、そのrepoのTaskを始める前に確認する。

新しいherness-html-syncはcoreとsupervisionの契約・portへ依存し、Tauri・Pi・具体的DBを参照しない。storeがH3の永続化portを実装し、desktopが組み立てる。coreからH2/H3へ逆依存させない。候補はprivateなアプリ領域のartifact handleで扱い、project外への一般書込み権限は増やさない。

各Taskは実行者、実コマンド、終了codeと実結果、対象revision、検証範囲・未確認事項を報告する。通常テストは一時project/DB、fake credential、loopbackのみ。既存Keychain探索・login・実model送信をしない。新規test targetはそのTaskで作成し、存在しないコマンドの成功を報告しない。Target文書を編集したら、別操作でHTMLを著作して共通検証する。本planの保存は実装開始・実接続・push・mergeの許可ではない。

Task 1: 共通source unitとsemantic契約を定義する

Dependencies / spec: 先行Taskなし。H3 Authoring and source fidelity、Common SDD policy and offline evidence。packの2026-09-01-agent-authored-html-design.mdとADR 0002・0003を読む。

Paths / deliverable: packのhtml_units.py、test_html_units.py、HTML正本specとREADME。Python標準ライブラリだけのlosslessなsource scanner、source unit・対応表・receiptのversion 1 schemaを定義する。strictは既存契約、semantic-v1は明示opt-inの追加とする。

Acceptance: UTF-8 byte範囲・種別・親子関係・IDを原文digestへ束縛する。見出し、段落、nested list、表のheader/cell、code、inline code/link、用語とAvoidを網羅し、未対応構文を黙って落とさない。schemaは未知field/版・重複IDを拒否し、厳密保持対象・根拠・計算・評価receiptの必須fieldを固定する。Targetのdocs/sdd/adr受理差異も共通resolverで修正する。新しい依存、renderer、新しいTarget種別は導入しない。

Verification / evidence: packでpython3 -m pytest tests/test_html_units.py tests/test_html_policy.py -q。CRLF・日本語byte位置・重複見出し・空文書・未対応構文・Target階層・symlinkの結果、schema fixture、変更TargetのHTML検証を報告する。ADRの過去の判断を無断で書き換えない。
