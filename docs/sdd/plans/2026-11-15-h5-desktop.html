H5 Chat-centered Desktop and Personal macOS Bundle Implementation Plan

Goal: チャット中心のhernessでSDD設計から承認済みplanの実行まで操作でき、本体と固定版SDD packを含む個人用macOSアプリとして導入できるようにする。

Architecture: H1の会話・履歴・skill・設定契約とH4の一覧・停止照合・finish契約を先行実装し、Rust hostの実行・保存所有を維持する。vanilla JavaScriptのUIを責務別ES modulesへ分割し、未信頼文書はIPCのないnative WKWebViewで閲覧する。版固定packをbundle資源へ含め、外部toolchainを診断して利用者の導入へつなぐ。

Tech Stack: Rust 1.97.1 / Cargo workspace、Tauri 2.12.5 / tauri-build 2.7.4、固定pi-rust、SQLite、macOS AppKit / WebKit、HTML/CSS/JavaScript ES modules、Python 3.11+標準ライブラリ、Git、開発用tauri-cli 2.11.0。

Spec: docs/sdd/specs/2026-11-15-h5-desktop-design.md

Global Constraints

以下はH5 specの原文を引き継ぐ。H1/H4のH5 integration additionsも承認済みの正本として全Taskへ渡す。

  • 自分のApple Silicon Macで、Finderから起動し、プロジェクトを開いてSDDによる設計相談・specレビュー・plan作成・承認済みplan実行へ進める。
  • 同じ通常会話へ追加入力し、閉じた画面やアプリ再起動後も保存済みの会話・実行・承認待ちを探せる。復元だけで送信・実行しない。
  • 変更理由をチャット以外の専用画面から確認し、Task・HTML同期・証拠・予算・停止理由と必要操作を追跡できる。
  • 本体とSDD packを同梱する。Git・Python 3.11+・利用者のbuild/testツールは同梱せず、不足・版不一致・設定方法を示してインストールを促す。
  • 一般公開、Intel・他OS、古いmacOSへの互換保証、Developer ID署名・notarization・App Store・自動更新、クラウド同期・telemetryは初期範囲外。
  • IDE・汎用ファイル編集器・ターミナル、会話の分岐・履歴編集・削除、資格情報や履歴の削除UI、worktree削除、新しい統合実行機構は追加しない。自動push・merge・公開、Task並列化、UIによる完了宣言は行わない。
  • 実行と保存はRust hostが所有する。UIは表示用cacheと選択・未送信draftだけを持ち、window・表示中project・pollの有無を進行条件にしない。UI設定はprivate app領域へ保存し、実行承認・条件・予算を画面設定で置き換えない。
  • SDD文書を書き込む会話では、開始前にH3の設定承認と有効なhost-delegated HTML契約を確認する。親のHTML著作・HTML worker dispatchへfallbackせず、文書変更後の同期・証拠はH3へ委譲する。同期が必要なレビュー・commit・後続操作は各正本のbarrierを満たしてから進める。H4の開始前には、同じ実checkoutで編集可能な通常runの停止も確認し、動作中の編集とTask所有を競合させない。
  • Taskが同じcheckoutを所有している間も、別の通常会話で読取り専用の相談を行える。hostがread・searchだけのgrantを適用し、write・edit・shell・Git変更を拒否する。子ログの入力欄は設けない。停止要求だけで編集を解禁せず、停止確認と所有状態を照合する。編集を伴う送信は利用者が改めて範囲を選び、重要なTask変更はH4のplan修正・再承認へ案内する。H4停止でも着手済みTaskの契約変更が自動移行可能になるわけではない。
  • 更新は対象project・安定ID・request ID・expected revisionへ結び付ける。同じ要求の再配送には同じIDを使い、別内容に同じIDを流用しない。競合は最新状態を読み直して人間へ戻す。通信timeout後に新しいIDで開始・送信・commitをやり直さない。H4の10種のerrorとH1/H2/H3のsanitized診断・参照・必要操作を保持し、生のprovider errorや資格情報を表示しない。
  • 通常会話本文はテキストと安全なMarkdown表現として表示し、raw HTML・script・実行リンクを受け入れない。モデル本文やrepo内文字列から操作確認を偽造できないよう、承認UIはhostの構造化状態だけから構成する。mainの画面切替にURL query・fragment・remote originを使って既存caller guardを緩めず、未信頼previewへcommand権限を与えない。
  • 軽さの数値上限は未合意である。既存debug測定の起動中央値337 ms・idle約204.5 MiBは参考で、releaseや全実行時の保証へ流用しない。初回release計測後、H5受入前に起動・idle・実行時の数値基準を人間と合意し、未合意のまま軽量性を達成済みとしない。
  • H5のUI/bundle検証と製品全体の受入を区別する。上流の未確認・画像/品質能力不足・利用条件未確認を免除せず、必要な機能は利用不可/保留と表示する。全体完成条件が成立しない間はherness全体の完成を主張しない。限定受入へ変える場合は別途人間の明示合意を必要とする。

File structure

本planはロードマップのH5だけを扱う。H5 specとH1追加契約、H4追加契約は2026-11-15に承認済み。以下のH1・H2・H3・H4・H5はそれぞれの正本specを指す。全briefへ正本パス・適用section・Global Constraintsを渡し、会話記憶を前提にしない。

調査起点はherness 9256cc5、承認記録は1a8ff09、DB schema 11、host-state format 3。pack入力の検証基準は../sdd/.worktrees/h4-execのb210b3aac3faf84c5ad201aa6502dface8c4cdf2で、../sddのmainと混同しない。実装開始時にHEAD・status・pack実パス/指紋を再確認する。packは読取りと配布artifact作成の入力だけで、別repo編集・mergeは本planに含めない。

本planは既存ホストでH5を開発する従来形式のplanであり、製品H4へ取り込む新形式planではない。製品向けsdd-execution-v1は受入fixtureとして別途用意する。開発controller/実装者は既存sdd-executeの直列dispatch・Task単位commitに従い、製品内の子にcommitさせない制約と混同しない。隔離はsdd-execute開始時に一度だけ確認し、今回はworktreeを作らない。

通常検証は一時repo/DB・fake credential・loopbackのみ。既存Keychain itemを探索せず、実login・実providerへ送信しない。新test targetは担当Taskで作ってから以下のコマンドを使う。全Taskは実行者、正確なcommand、exit/output、対象revision、検証範囲・未確認を報告する。Target Markdownの変更はHTMLを別操作で著作・検証してからcommitする。

Task 15のpreview専用試験は既存H3 render testと同様に通常debug binaryを使う。Task 16からnative UI fixture用binaryをtarget/h5-ui-tests/debug/herness-desktopへ分離し、tests/desktop-uiのrunnerはその実pathとfeatureを照合する。各native testの起動時はHERNESS_DESKTOP_BINに対応する絶対pathを設定する。Task 16以降、UI変更がbinaryへ埋め込まれるたびに専用buildを更新し、通常のdebug/release buildで上書きしない。product .appの試験は別の明示artifact pathを渡す。新規JS moduleのテストも実WebKitのharnessで行い、製品用Node依存を導入しない。

Task 11: H4の停止照合を人間操作へ接続する

Dependencies / spec: Tasks 6・10。H4 H5 integration additions 2、Durable state, plan changes and finish、Numeric defaults and lifecycle。H1 Lifecycle and recovery。
